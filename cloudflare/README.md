# Cloudflare Worker — обход блокировок сети

## Зачем

Приложение ходит только на `jdjgrczsnhroqjasipai.supabase.co`. Часть
мобильных сетей (сотовые операторы, отдельные Wi-Fi, APN) режет или душит
этот домен — без VPN приложение не грузится.

Worker ставится перед Supabase. Клиент общается с обычным доменом
Cloudflare, Worker пересылает запросы дальше. Фильтр по домену
`supabase.co` больше не применяется.

**Что это не даёт:** никакой защиты данных. Ключ anon публичный по
замыслу, доступ ограничивают RLS в базе. Задача воркера — обойти сетевой
фильтр, а не спрятать базу.

## Файлы и аватарки: обязательный передеплой

**Воркер, который сейчас развёрнут, отдаёт файлы обрезанными.** Проверено
21.10.2026 на аватарке 194 КБ:

| запрос | что приходит |
| --- | --- |
| напрямую в Supabase | 194 КБ за 0,18 с |
| через воркер | заголовок `Content-Length: 193933`, а тела — **22 КБ** и тишина до таймаута |
| через воркер, `Range: bytes=0-16383` | ровно 16 КБ за 0,1 с |

Из-за этого на сетях с заблокированным `*.supabase.co` чаты работали, а
фотографии, аватарки, голосовые и кружки — нет.

Приложение 1.1.5 научилось обходить это: тянет файл кусками по 16 КБ,
каждый — отдельным соединением (по одному соединению второй кусок
зависает). Так медиа работает даже со старым воркером. Но это 12
запросов вместо одного на аватарку и 60 вместо одного на скриншот —
поэтому воркер всё равно надо обновить.

Как задеплоить:

1. Открой <https://dash.cloudflare.com> → **Workers & Pages** →
   `luxe-proxy`
2. **Edit code**
3. Выдели всё (`Ctrl+A`) и вставь содержимое `cloudflare/worker.js`
4. **Deploy**

Проверка, что обновился: открой в браузере

```
https://luxe-proxy.gfpmmp.workers.dev/health
```

Должно вернуться `{"ok":true,"storage":"buffered","version":3}`.
Старый воркер на этот адрес отвечает 404 от Supabase. Приложение
спрашивает это при запуске и само переключается на загрузку одним
запросом, как только увидит новый ответ.

## Ключи TURN для звонков (Cloudflare Realtime TURN)

Без TURN звонок не соединяется там, где сеть режет UDP. Например,
мобильный интернет без VPN: STUR пробивает NAT и узнаёт адрес, но голос
через него передать нельзя — ICE не находит ни одной рабочей пары
адресов и звонок висит до таймаута.

Cloudflare даёт ретрансляцию бесплатно, но ключи у него короткоживущие:
их надо запрашивать по API. Токен Cloudflare **нельзя** зашивать в
приложение — его вытащат из APK и будут слать запросы за твой счёт.
Поэтому ключи запрашивает Worker, а секрет живёт в его переменных.

### Настройка

1. Cloudflare → **Realtime** → включи **TURN**, создай ключ.
   Получишь **Key ID** и **API Token**.
2. В Worker открой **Settings** → **Variables and Secrets** и добавь
   два секрета (именно **Secrets**, не Variables):

   | Имя | Значение |
   |---|---|
   | `CF_TURN_KEY_ID` | Key ID из шага 1 |
   | `CF_TURN_TOKEN` | API Token из шага 1 |

3. Задеплой воркер заново.

### Проверка

Открой в браузере

```
https://luxe-proxy.<ник>.workers.dev/turn-credentials
```

Должен вернуться JSON вида:

```json
{"iceServers":[
  {"urls":["stun:stun.cloudflare.com:3478"]},
  {"urls":["turn:turn.cloudflare.com:3478?transport=udp", "..."],
   "username":"...","credential":"..."}
]}
```

Если вместо этого `TURN не настроен` — секреты не заданы или
переименованы. Если `Cloudflare отказал выдать ключ` — ключ выключен
или истёк.

**Эндпоинт — `generate-ice-servers`.** Без этого суффикса Cloudflare
отвечает 404, ключи не выдаются, а звонки продолжают не соединяться
так, будто TURN не настроен вовсе.

**Если адрес недоступен из твоей сети** — приложение попробует второй
(`jdjgrczsnhroqjasipai.supabase.co/turn-credentials`), но там маршрут
тоже ведёт в этот же Worker, так что при полной блокировке Cloudflare
поможет только свой TURN на своём VPS.

## Настройка

### 1. Создать воркер

1. Открой <https://dash.cloudflare.com> → **Workers & Pages**
2. **Create** → **Create Worker**, имя `luxe-proxy`
3. **Deploy**

Открывшийся адрес вида `luxe-proxy.<ник>.workers.dev` — он понадобится
в приложении. Отдельный домен не нужен, `workers.dev` бесплатен.

### 2. Залить код

Worker создан с файлом `index.js`. Замени его содержимое на
`cloudflare/worker.js` из этого репозитория и нажми **Deploy**.

В коде проверь строку:

```js
const UPSTREAM_HOST = 'jdjgrczsnhroqjasipai.supabase.co';
```

### 3. Проверить, что работает

Открой в браузере (на том самом телефоне, где не работает):

```
https://luxe-proxy.<ник>.workers.dev/auth/v1/health
```

Ответ `{}` — значит воркер видит Supabase и всё настроено.
Пустая страница или ошибка — проверь, что адрес воркера верный.

### 4. Включить прокси в приложении

Адрес передаётся при сборке, менять код не нужно:

```cmd
flutter build apk --release --dart-define=SUPABASE_URL=https://luxe-proxy.<ник>.workers.dev
```

Или для Windows:

```cmd
flutter build windows --release --dart-define=SUPABASE_URL=https://luxe-proxy.<ник>.workers.dev
```

Для iOS в `codemagic.yaml` добавь в секцию сборки:

```yaml
    args:
      - --dart-define=SUPABASE_URL=https://luxe-proxy.<ник>.workers.dev
```

Если адрес станет постоянным — впиши его в
`lib/config/supabase_config.dart`, поле `_proxyUrl`, тогда `--dart-define`
не понадобится.

## Статус

Прокси развёрнут и работает: `https://luxe-proxy.gfpmmp.workers.dev`

Адрес **вшит в приложение по умолчанию** (`lib/config/supabase_config.dart`,

## Почему чаты грузились, а список — нет

Симптом был обманчивый: вход работал, проверка связи проходила, а список
чатов висел по таймауту. При этом **тот же адрес из браузера отвечал за
секунду**.

Логи Worker показали, что все четыре запроса из приложения доходят до
Supabase и возвращают ответ за 300 мс. Значит дело было не в сети и не в
Worker, а в обратном пути — от Worker к телефону.

Причин было три, все в теле Worker:

1. **Сжатие.** Supabase отдаёт gzip, Worker распаковывает тело, но
   заголовок `content-encoding` уходит клиенту вместе с уже распакованными
   байтами. `dart:io` после этого молча ждёт данных, которых не будет.
   Лечится `Accept-Encoding: identity` в запросе к Supabase.

2. **Поток вместо целого ответа.** `new Response(upstream.body)` отдаёт
   тело частями. Телефон держит соединение и ждёт продолжения, которого
   уже не будет, пока не сработает таймаут. Лечится сборкой ответа целиком
   через `arrayBuffer()`.

3. **Свой `content-length`.** После сборки тела его длина известна, и
   соблазн выставить заголовок вручную велик. Но Cloudflare сжимает ответ
   под `Accept-Encoding` телефона, и выдуманная длина перестаёт совпадать с
   тем, что уходит по проводу. Клиент считает, что тело не дописано, и ждёт
   недостающие байты. Лечится отказом от заголовка — длину считает платформа.

Файлы из `/storage/v1/object/` раньше тоже шли потоком — и именно они
обрывались на 22 КБ. Теперь собираются целиком, поток остался только
для файлов больше 45 МБ.

Проверить: логи пишут размер отданного тела — если строка
`отдаём 430 байт для /rest/v1/chat_members` есть, Worker отдал данные
целиком. Если после этого приложение всё равно показывает таймаут,
значит ответ теряется уже на пути к клиенту.

## Логи Worker

В воркере включён `console.log` на каждый запрос:

```
GET /rest/v1/chat_members?select=chat_id -> 200 за 142мс
```

Открыть: **Workers & Pages → luxe-proxy → Observability → Workers Logs**,
нажать **Live** и держать открытым, пока в приложении жмёшь «Повторить».
Если запрос от приложения не появляется — значит он не доходит до Worker,
и затык в сети между телефоном и Cloudflare.

## Ограничения, о которых стоит знать

- **Бесплатный план — 100 000 запросов в сутки.** Для мессенджера с
  десятками пользователей хватает; для тысяч — уже нужен платный тариф.
- **`workers.dev` режут реже, но тоже режут.** Если блокируют и его —
  нужен свой домен: добавить воркеру домен в разделе Custom Domains.
- **Данные идут через Cloudflare.** Это ещё один посредник в цепочке.
  Для мессенджера с шифрованием от клиента до клиента это имело бы
  значение; здесь переписка и так шифруется только на участке
  клиент→Supabase.
- **Worker не ускоряет связь** сам по себе. Он добавляет один хоп, зато
  перестаёт упираться в фильтр.

## Откат

Если что-то пошло не так, убери `--dart-define=SUPABASE_URL` и
пересобери: приложение вернётся на прямой адрес Supabase.
